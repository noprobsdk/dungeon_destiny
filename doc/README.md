# Design documentation

`doc/` is the canonical home of Dungeon Destiny's intended design.

It may describe:

- unresolved ideas and alternatives;
- accepted game-design decisions;
- current and future gameplay systems;
- UX intentions;
- data-model intentions;
- technical and 3D-production contracts.

A statement in `doc/` is not evidence that the corresponding capability has been implemented or released.

## From design to implementation

When part of the design is selected for development, a GitHub Feature must identify:

- the relevant design sources;
- the selected scope;
- exclusions;
- affected targets;
- acceptance criteria;
- dependencies and risks.

GitHub tracks implementation. Released and verified behaviour is documented separately under [`delivery/`](../delivery/).

## POC knowledge

Historical POC findings may later be added under `doc/00-project-history/`. They remain evidence and lessons, not approved architecture or released functionality.
